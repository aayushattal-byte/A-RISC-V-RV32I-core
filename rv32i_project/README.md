# RV32I single-cycle Verilog processor

## Quick start

Install Icarus Verilog and GTKWave. From the project directory:

```bash
python3 programs/make_programs.py
bash run_sim.sh
gtkwave results/rv32i.vcd
```

The testbench runs sum(1..10)=55, Fibonacci F(10)=55, and byte/halfword/word load/store=123. It prints PASS/FAIL and exits nonzero on failure. `results/rv32i.vcd` is generated by simulation.

## Vivado simulation

1. Create an RTL project; add `rtl/rv32i_core.v` as a design source.
2. Add `tb/tb_rv32i.v` as a simulation source; set `tb_rv32i` as simulation top.
3. Add the three `programs/*.hex` files as simulation memory files; make sure the simulator working directory contains a `programs/` directory with these files. Alternatively, run the provided script from a shell with Icarus Verilog.
4. Run Behavioral Simulation, then inspect `pc`, `ins`, `regs[10]`, `halted`, `fault`, and `debug_result`.

## FPGA (Spartan-7 XC7S50)

1. Create Vivado RTL project for your **exact** XC7S50 package/speed grade.
2. Add `rtl/rv32i_core.v` and `fpga/top_spartan7.v`; set `top_spartan7` as synthesis top.
3. Add `programs/sum.hex` as a memory initialization source, preserving the relative path or updating `$readmemh` accordingly.
4. Create an XDC constraint file with the board's **actual** oscillator, reset button, and LED package pins. The pin map is board-specific; do not guess pin assignments.
5. The divider assumes a 100 MHz oscillator and generates a 2 Hz clock. For a different board clock, adjust divider and clock constraints.
6. Synthesize, implement, generate bitstream, open Hardware Manager, program FPGA, press reset and observe the LEDs. After halt, the sum program outputs decimal 55 = binary `00110111` on LEDs [7:0]. During execution LEDs show PC bits; `FF` signals fault.
7. Record actual LUT/FF/BRAM utilization, WNS, clock frequency, and a board photograph; these cannot be truthfully supplied without the board and Vivado run.

## Scope and limitations

Implements base RV32I computational, control flow, load/store instructions, ECALL excluded, EBREAK as a simulation/application halt, FENCE treated as NOP. Does not implement CSRs, exceptions, interrupts, atomic instructions, multiplication/division, compressed instructions, or a privileged architecture. Misaligned memory accesses and illegal opcodes set `fault`. The core has small fixed 1 KiB instruction/data spaces and asynchronous instruction/data reads. These are convenient for learning and simulation but may infer distributed memory and have a long single-cycle critical path on FPGA. This is an educational RV32I subset of the execution environment, not a full RISC-V compliance-certified SoC. The demo divider creates a derived clock; for production FPGA designs use clock enables or dedicated clocking resources.

## Verification note

Three application tests are not a complete ISA verification suite. Add directed tests for all RV32I opcodes, branch cases, signed/unsigned arithmetic, shifts, x0, alignment, and randomized differential testing against an ISA reference model before claiming complete ISA compliance.
